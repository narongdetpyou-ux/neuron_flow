# ชุดคำตอบอ้างอิง Neuron Flow 0.2.0

ชุดนี้ล็อกก่อนเพิ่มตัวรับ CSV และตัวตรวจรุ่นใหม่ มี **100 เอกสาร: 80 VALID และ
20 INVALID** ไม่มี ERROR ที่เกิดจากข้อมูลเข้าเพียงอย่างเดียว สัดส่วนนี้เป็นการออกแบบ
ชุดตรวจรับ ไม่ใช่สัดส่วนข้อมูลใช้งานจริงหรือขีดจำกัดของระบบ

- `input.csv`: UTF-8 ไม่มี BOM มีหัวตารางตามสัญญารุ่นใหม่
- `expected_results.json`: คำตอบรายเอกสารและเหตุผลรายจุด
- `cases.json`: ชื่อกรณี ขอบเขต และรหัสเหตุผลที่คาด
- `fixture_lock.json`: SHA-256 และขนาดไบต์ของไฟล์ทั้งสาม พร้อมประวัติการเปลี่ยนล็อก

สร้างซ้ำหรือยืนยันโดยไม่เขียนไฟล์:

```bash
python tools/build_acceptance_fixture.py
python tools/build_acceptance_fixture.py --check
```

ตัวสร้างไม่ import `neuron_flow` ไม่ใช้ Decimal หรือ float คำตอบยอดเงินคำนวณด้วย
integer สตางค์ เหตุผลของ INVALID กำหนดล่วงหน้าตามสถานการณ์ ไม่ได้เรียกตัวตรวจ
ที่จะพัฒนาในขั้นต่อไปเพื่อสร้างคำตอบของตัวเอง `INV-001` เป็นตัวอย่างเดิม 310.70 บาท
และมีกรณีขอบเขตจำนวน/ราคา ราคาศูนย์ UTF-8 เครื่องหมาย comma/quote และข้อความหลายบรรทัด

## สัญญาคำตอบ

`documents` เรียงตามลำดับเอกสารที่พบครั้งแรก ค่าเงินเป็น string ทศนิยมสองตำแหน่ง
`difference` เท่ากับ `computed_total - declared_total` เลข `source_rows` และ
`errors[].row_number` เป็น **บรรทัดจริงเริ่มต้นของ CSV record** เริ่มนับหัวตารางที่ 1
record ที่มีข้อความหลายบรรทัดจึงทำให้หมายเลข record ถัดไปขยับมากกว่าหนึ่ง

เอกสาร INVALID มี `computed_total` และ `difference` เป็น null เพราะไม่รับรองยอด
ยกเว้น `TOTAL_MISMATCH` ซึ่งคำนวณยอดและผลต่างได้ `declared_total` ใช้ค่ามาตรฐาน
จากแถวแรกเมื่อรูปแบบถูกต้อง แต่เป็น null เมื่อหายหรือขัดกันระหว่างแถว

เหตุผลแต่ละจุดมี `row_number`, `field`, `reason_code`, `expected`, `actual`
โดย `actual` เป็นข้อความ CSV ต้นทาง และ `expected` เป็นข้อกำหนดสั้นคงที่หรือยอดอ้างอิง
ถ้า currency ว่างให้ REQUIRED เท่านั้น; currency USD ที่ขัดกับ THB ในแถวแรก
ให้ทั้ง CURRENCY_UNSUPPORTED และ CURRENCY_CONFLICT อย่างละจุด

| reason_code | ความหมาย |
| --- | --- |
| REQUIRED | ช่องบังคับว่าง |
| QUANTITY_FORMAT | จำนวนไม่ตรงรูปแบบจำนวนเต็มบวก 1–7 หลัก |
| QUANTITY_RANGE | จำนวนอยู่นอก 1–1,000,000 |
| PRICE_FORMAT | ราคาไม่ตรงรูปแบบตัวเลขไม่ติดลบ ทศนิยมไม่เกิน 2 ตำแหน่ง |
| PRICE_RANGE | ราคามากกว่า 1,000,000,000,000 บาท |
| DUPLICATE_ITEM_ID | รหัสรายการซ้ำภายในเอกสาร |
| CURRENCY_UNSUPPORTED | สกุลเงินไม่ใช่ THB |
| CURRENCY_CONFLICT | สกุลเงินต่างจากแถวแรก |
| DECLARED_TOTAL_CONFLICT | ยอดที่ระบุต่างจากแถวแรก |
| TOTAL_MISMATCH | ยอดที่ระบุไม่ตรงยอดคำนวณ |

ชุดข้อมูลหลักนี้ครอบคลุมกรณีข้อมูลของ A01 และ A03–A07 ส่วนหัวตารางผิด (A02),
แถวที่ไม่มี document_id (A08), UTF-8 BOM, การไม่ retry ข้อมูลผิด และเหตุระบบล่ม/
หยุด/เปิดต่อ/ขัดแย้ง (A09–A12) ต้องมีการตรวจแยกในขั้นถัดไป จึงยังไม่ใช่ผลตรวจรับ
ว่ารุ่น 0.2.0 ผ่านครบทุกข้อ

การเปลี่ยนคำตอบที่ล็อกต้องตรวจทานเหตุผลและกรณีที่ได้รับผลกระทบก่อน จากนั้นใช้
`python tools/build_acceptance_fixture.py --update-lock --reason 'เหตุผลที่ตรวจทานแล้ว'`
ตัวสร้างจะเก็บ SHA-256 เดิมไว้ในประวัติ การรันปกติจะปฏิเสธการเขียนทับไฟล์ที่ขัดกับล็อก

## หลักฐานยืนยันก่อนเริ่มตัวรับ CSV

รันตัวสร้างและ `--check` สำเร็จ ได้ 100 เอกสารจาก 201 CSV records ข้อมูล
แบ่งเป็น 80 VALID, 20 INVALID, 0 ERROR และไม่มีแถวที่จัดกลุ่มไม่ได้

ตรวจอิสระเพิ่มเติมโดยอ่าน CSV ด้วย `csv.DictReader` แล้วใช้ `decimal.Decimal`
คูณราคาและจำนวนจากต้นทางโดยตรง ผลของ VALID ทั้ง 80 ใบและกรณี TOTAL_MISMATCH
ตรงกับคำตอบ integer สตางค์ทุกใบ ผลต่างตรงกัน รวมถึง `INV-001` เท่ากับ 310.70 บาท
ตรวจด้วยว่า source_rows ทุกใบตรงกับ physical line เริ่ม record, ทุก error อ้างแถว
ของเอกสารนั้น, INVALID อื่นมี computed_total/difference เป็น null, จำนวน cases ครบ
100 และ SHA-256/ขนาดทั้งสามไฟล์ตรงกับล็อก ผลตรวจทั้งหมดผ่าน การตรวจนี้ยืนยัน
ความสอดคล้องของชุดคำตอบก่อนพัฒนา ไม่ใช่ผลทดสอบของตัวรับหรือตัวตรวจรุ่นใหม่

SHA-256 ของ `expected_results.json` ที่ล็อกไว้:

```text
f72f753bb474b4e94743f3c917227625c5a8b0eb556e50c91fe6f3a90dd20b26
```
