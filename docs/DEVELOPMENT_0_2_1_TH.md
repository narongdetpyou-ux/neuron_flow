# แผนพัฒนา Neuron Flow 0.2.1

**สถานะรุ่นปัจจุบัน: 0.2.1 เผยแพร่แล้วเมื่อ 28 ตุลาคม 2026; Colab จริงยัง `not_run`**
ดู [บันทึกหลังเผยแพร่](../verification/publication_2026_10_29/README.md) และ
[stage gates ของรุ่นเผยแพร่](../verification/v0_2_1/stage_gates.json)
เนื้อหาถัดไปเก็บแผนและเกณฑ์จากช่วงพัฒนาเดิม คำว่า candidate ในแผนไม่ใช่สถานะ release ปัจจุบัน
รุ่น 0.2.0 เป็นรุ่นเผยแพร่แล้วโดยมีข้อจำกัดที่เปิดเผยว่า Colab จริงยังไม่ได้ตรวจ
การพัฒนา patch นี้ไม่เปลี่ยนประวัติการอนุมัติหรือหลักฐานผลตรวจของ 0.2.0

เป้าหมายของรอบนี้คือเปิดงานเดิมต่อได้สะดวกและตรวจขอบเขตการทำงานให้ชัด
คงสัญญา CSV ผลตรวจเงิน และคำตอบอ้างอิงเดิม ไม่ขยายไป OCR/PDF ภาษี ส่วนลด
หลายสกุลเงิน หรือ scheduler หลายเอกสารพร้อมกันในรอบนี้

## ลำดับงานและเกณฑ์ผ่าน

### 1. กำหนด patch compatibility ที่ตรวจได้

รับรองการอ่านและเปิดต่อ workspace 0.2.0 ด้วย candidate 0.2.1 เฉพาะ contract/Agent versions
และรูปแบบเก็บข้อมูลที่ตรวจว่าความหมายตรงกัน ไม่ขยายเงื่อนไขเป็นยอมรับทุกเวอร์ชัน

**ผ่านเมื่อ:** งานสำเร็จของ 0.2.0 ใช้ผลเดิมได้โดยไม่เพิ่ม attempts/history หรือเปลี่ยน bytes/hash/mtime
ของรายงาน frozen payload และรุ่นที่บันทึกในผลเก่ายังเป็นข้อมูลเดิม งานใหม่บันทึกรุ่นจริง
ข้อมูล contract หรือ Agent ที่ขัดกันยังถูกปฏิเสธและรักษาผลเดิม
ครอบคลุมงานที่จบแล้ว งานที่ค้าง งานที่หมดจำนวนครั้ง และช่วงส่งรายงานแต่ยังไม่มี receipt

### 2. แยกการรับงานออกจากการประมวลผล

เพิ่ม `csv --submit-only` ให้บันทึก source/identity และคืน batch_id ก่อนเริ่ม Agent
ผู้ใช้และ Notebook เก็บรหัสเพื่อเปิดต่อได้แม้งานใช้เวลานานหรือ controller ถูกหยุด
การเรียก `csv` ตามปกติยังประมวลผลและส่งรายงานตามพฤติกรรมเดิม

```bash
python -m neuron_flow csv input.csv --submit-only --workspace batch_workspace
python -m neuron_flow batch-resume <batch_id> --workspace batch_workspace
```

**ผ่านเมื่อ:** submit-only ไม่เปิด worker และไม่เพิ่ม attempts;
รับงานเดิมซ้ำได้โดยไม่เพิ่มเอกสาร; ใช้รหัสเดิมกับข้อมูลต่างกันยังเกิด conflict
การเปิดต่อมีผลเหมือนการรันปกติ และสถานะรับงานไม่ถูกแสดงเป็นผลตรวจเอกสารสำเร็จ

### 3. ค้นหา batch โดยอ่านอย่างเดียว

เพิ่ม `batch-list --workspace ...` เพื่อค้นรหัส สถานะ และข้อมูลพอเลือกงานที่จะเปิดต่อ
โดยไม่ต้องมี CSV ต้นทางหรือผล CLI/session metadata จากครั้งก่อน
คำสั่งอ่านต้องใช้ได้ขณะ controller ตัวเดิมกำลังทำงาน

```bash
python -m neuron_flow batch-list --workspace batch_workspace
```

**ผ่านเมื่อ:** ไม่มีการรัน Agent ไม่ยึด controller lock ไม่สร้างงาน/ตาราง/ฐานข้อมูลใหม่
และไม่เปลี่ยน attempts/events; workspace ที่ไม่มีอยู่หรือใช้รูปแบบไม่รองรับได้รับคำอธิบายชัดเจน
ขณะมี writer อ่าน snapshot ที่สอดคล้องกันได้โดยไม่รบกวนการทำงาน
ทดสอบการหา batch หลัง controller หยุดก่อนคืนผล CLI สุดท้ายแล้วเปิดต่อสำเร็จ

### 4. ตรวจขอบเขตข้อมูลและความล้มเหลวใน CI

ใช้ขอบเขตเดิม: CSV 16 MiB, ข้อความ engine 1 MiB, ข้อความรายการ 500 ตัวอักษร
และข้อกำหนดจำนวน/ราคา/รายการเดิม ตรวจขอบเขตเป็นไบต์เมื่อสัญญาระบุขนาดไบต์
รวมข้อความ UTF-8 ที่จำนวนตัวอักษรไม่เท่าจำนวนไบต์

**ผ่านเมื่อ:** มีกรณีต่ำกว่า/ตรง/เกินเพดานที่เกี่ยวข้อง ทั้ง input envelope, output และ job report
CSV ที่เกินเพดานไฟล์ถูกปฏิเสธก่อนเริ่มงาน; เอกสารที่ engine ยืนยันผลไม่ได้แสดง ERROR
พร้อมสาเหตุ โดยใบอื่นจบได้ ไม่มีแถวหาย ไม่ retry ข้อมูลผิดเกินกติกา และไม่ค้างไม่จำกัดเวลา
CI ทดสอบบน Python ขั้นต่ำที่ประกาศและรุ่นที่ใช้งานจริงตามขอบเขตที่เลือก
บันทึก versions/คำสั่ง/จำนวนกรณีจริง รวมการล่มหรือหยุด process ที่จำเป็นต่อเกณฑ์กู้คืน

### 5. ตรวจรวมและเตรียม Colab acceptance

- ตรวจ baseline เดิมและชุดใหม่แยกกัน อ่านจำนวน tests จากรายงานจริง
  ไม่ตรึงจำนวนชุดใหม่ไว้ที่ค่าของ 0.2.0 หลังเพิ่มกรณีตรวจ
- เทียบ 100 เอกสารกับคำตอบเดิมที่ล็อกครบทุกช่อง: 80 VALID / 20 INVALID;
  คง Decimal กับ integer สตางค์และการแยก document_status จาก engine_status
- สร้างรายงาน ตรวจ source provenance/hash และยืนยันว่าการเปิดต่อไม่ทำงานสำเร็จซ้ำ
- ปรับ README/Notebook/คำสั่งตรวจให้ตรง API ที่เสร็จจริง แล้วตรวจจาก ZIP ที่แตกใหม่
- ทำ Colab จริงตาม [COLAB_ACCEPTANCE_TH.md](COLAB_ACCEPTANCE_TH.md):
  ตรวจ 0.2.0 เป็นฐานก่อน แล้วตรวจ candidate 0.2.1 รวม restore รุ่นเดิมและ patch compatibility

**ผ่านเมื่อ:** ผลตรวจในเครื่องและขอบเขต CI ที่ประกาศผ่านพร้อมหลักฐาน ไม่มีการแก้ golden answers
หรือเขียนทับผลประวัติของ 0.2.0 และสถานะ Colab ตรงตามผลจริง
ขณะจัดทำแผนนี้ Colab ยังเป็น `not_run`; syntax/offline smoke ไม่ใช้แทน runtime จริง

## สิ่งที่ส่งตรวจของรอบนี้

โค้ดและ tests ของ compatibility/submit-only/list/limits, รายงานผลแยกสำหรับ 0.2.1,
README/Notebook ที่ใช้ API จริง, ZIP candidate พร้อม SHA-256 และรายการข้อจำกัดที่ยังค้าง
การผ่านชุดตรวจหรือการสร้าง ZIP ไม่ใช่คำอนุมัติเผยแพร่ 0.2.1

ผล Colab ต้องมีรุ่น runtime/Python เวลา input/output hashes snapshots attempts และ controller logs
รวมคำยืนยันว่าไฟล์ดาวน์โหลดถึงเครื่องจริง `release_ready`/การอนุมัติและ
`colab_acceptance_complete` เป็นคนละข้อมูล ห้ามทำให้ Colab เป็น true เพราะการอนุมัติเพียงอย่างเดียว

## งานที่แยกออกจาก patch นี้

การแก้สิทธิ์ native GitHub release assets ที่เคยพบ HTTP 401 เป็นงานช่องทางส่งมอบ
ต้องตรวจสิทธิ์ อัปโหลด ดาวน์โหลด และ hash จริงแยกจาก runtime tests
ไม่สรุปว่าแก้แล้วจากการสร้างไฟล์ในเครื่อง และไม่เผยแพร่ candidate โดยอัตโนมัติจากแผนนี้
ภายหลัง run #3 และบันทึกหลังเผยแพร่ยืนยันการส่งมอบ v0.2.1 จริงแล้ว โดยไม่เปลี่ยนผล Colab

การคืน workspace ต่าง absolute path และการเพิ่ม parallel scheduling หลายเอกสาร
ยังไม่รวมใน 0.2.1 การคืน backup รอบนี้คง path เดิม; การขยายขนาด/ความเร็วให้พิจารณาหลังมีผลวัด
และหลักฐาน Colab โดยตั้งเป้ารุ่นถัดไปแยกจาก patch ปัจจุบัน
